# Neko 1.2: character-sheet prompts

These are for you to generate with your image tool, using the Neko reference image. Every
sheet has **12 drawings: 4 columns × 3 rows**, read left to right, top to bottom. Each
action is split into numbered parts (`a`, `b`) and kept in order.

## How to generate each sheet

1. Attach **`assets/neko_idle.png`** as the character reference, every time.
2. For a part `b` sheet, also attach the finished part `a` sheet. Say: *"continue this exact
   sheet: same scale, same line weight"*.
3. Paste the **COMMON block** below, then that sheet's **SHEET block**.
4. If the result has a background, labels, a grid or a haze, run the **CLEANUP block** on it.
5. Save it as the filename given, in a new folder **`assets-incoming/`**. Don't put it in
   `assets/`; I import from there after checking.
6. **Rejecting is normal.** Check the following before saving:
   - exactly 4 legs, 2 ears, 1 tail
   - the face looks like Neko
   - all 12 kittens are the same size
   - nobody touches a neighbouring cell
   - every side pose faces **left**

   Regenerate if any of these fails. A wrong sheet costs more later than a re-roll now.

You don't need to get the timing right. I set durations, holds and travel in code. The
*Timing* notes are there so you know what each drawing is for.

### COMMON block (paste first, every time)

```
Use case: production pixel-art animation source sheet. Draw the SAME white kitten "Neko" from the reference image: white fur, soft gray underchin and chest, charcoal stepped pixel outlines, pink nose and inner ears, large dark eyes with small square white highlights, compact body, large round head, short fluffy tail. Keep hard pixel clusters (crisp pixel art, not smooth painting, no anti-aliased blur).

LAYOUT: EXACTLY 4 columns x 3 rows = 12 separate drawings, in chronological order left-to-right, top-to-bottom. One complete kitten per cell, centred, with wide fully transparent gutters; ears, paws and tail entirely inside the cell; no kitten touches another cell. All cells the same size.

BACKGROUND: true transparent alpha right up to the charcoal outline. No floor, ground line, shadow, haze, glow, props, hands, cursor, hearts, stars, motion lines, speed lines, sweat drops, text, numbers, labels, grid lines, borders or watermark.

CAMERA AND SCALE: fixed camera; the head is the SAME physical size in every cell; all side views face LEFT. Crouching, stretching or jumping changes joints and spine, never the overall size of the kitten. The body may get longer, lower or taller as the pose demands.

ANATOMY: exactly four legs (two forelegs, two hindlegs), one head on a visible neck, two ears, one tail attached at the rump. Far legs are partly hidden behind near legs, never duplicated. A lifted paw REPLACES its grounded version. Head, chest and pelvis are separate masses joined by a flexible spine: show the spine arching, stretching and gathering.

ACTING: expressions are DRAWN with eyelids, eye shape, ears, mouth and head angle, never written on the face as symbols. Use the eye vocabulary named below (happy squeeze = eyes closed in soft upward arcs; half-lids = flat upper lid over the eye; wide = slightly larger round eyes).

Cell 1 of every sheet (unless told otherwise) is Neko's neutral seated pose from the reference: front view, sitting upright, paws together, tail curled to the right side, calm open eyes, tiny closed mouth.
```

### CLEANUP block (only if needed)

```
Clean this animation sheet. Preserve EVERY kitten drawing exactly: pose, order, size, face and the 4 x 3 layout. Remove all labels, numbers, grid lines, borders, background, floor, shadows, glow, haze, stray fragments and motion marks. Make the background true transparent alpha right up to each charcoal outline, keeping the white fur inside every outline. Output twelve isolated kittens with empty transparent gutters.
```

## What happens when you hand them over

For each sheet I will:
1. Check the actual drawings (count, anatomy, size) and list any cell that needs a re-roll.
2. Import at Neko's fixed scale, register the feet and connect the first and last cells to her
   real idle.
3. Show you native-size previews, plus an old/new comparison where a drawing replaces
   something (the Catch wins).
4. Record the prompt and assembly in `docs/v1.2-prompts.json`, as earlier releases did.

The accepted tail chase and catch are not touched by any of this.
