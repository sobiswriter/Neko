# Journal coherence and50-entry retention · 2026-10-23

The user reports that logs do not agree with Neko's actions and asks to retain only the latest50 entries. This corrects observation/retention; it does not change any sprite, animation cadence, sleep timer, game qualification or dialogue selection.

## Causes and correction

`refresh_asset` logged a state as soon as a clip was selected. Several selections can happen before the next paint, or while hidden, so the journal could describe a performance that never appeared. Game phases were similarly recorded during model updates. State/phase events now follow the actual Neko painter. The recorded clip follows the real frame selection, including dynamic held expressions, reduced-motion static poses and fallback resources. Repaints of the same presentation do not duplicate state events; hiding/re-showing begins a new observed presentation. Typing/window activity reactions are recorded when their selected presentation is painted and discarded if superseded beforehand.

Thoughts were called shown immediately after `show()`. A second thought could replace the first before any paint. `ThoughtLabel` now signals its first actual text paint once per presentation and its dismissal; the journal records the painted words/channel and their hide. Suppressed/deferred requests remain explicitly labelled. Pet attempts are no longer reported as accepted before guards run; accepted/queued/comfort interactions and requests waiting for safe game recovery are distinct from the eventual painted care action. Game session creation, invitation acceptance, observed phase and completion are separate events. Visibility records follow the real Qt show/hide events, including fullscreen visibility changes.

Reject treating selected model states, screenshots created while hidden, `show()` requests or ignored clicks as proof of an on-screen action. The independent observer comparison below tests the painter rather than re-reading the same journal callback.

## Retention

Both the in-memory journal and `neko-events.jsonl` contain at most the latest50 valid events. Each update atomically replaces a small snapshot; it no longer appends indefinitely or creates a rotated backup. Startup scans existing history with bounded event memory, ignores malformed rows, keeps the latest50 valid rows and removes `neko-events.previous.jsonl`. The old rotated file is also removed on subsequent successful saves. Internal invitation/game debug buffers now also cap at50.

An interrupted/failed replacement preserves the previous complete saved file; recent events remain visible in memory and the Journal shows the storage error. A later successful write persists the current50 and retries old-file cleanup. The50-event limit is global across categories and sessions, not50 per filter. The existing JSONL schema/filter/copy behavior and local privacy boundaries remain; no raw keys, typed text, window titles, cursor trails or uploads are introduced.
